# Purpose

The port of Elements' DSP to Rust: the part, its voice, its exciters, its three resonators, its
reverb and its hidden second voice, from Emilie Gillet's MIT code, `pichenettes/eurorack`
`elements/dsp/` at commit `f4cfa7697095a28d292bff758beb51deb49b5a86` and `pichenettes/stmlib` at
`e3bd7c9cc00e4364166f9905c0509b6ffd0535ec`. **Held bit for bit to that C++**: the floats a case
renders here equal, to the bit, the floats the C++ part renders, and so do the module's 16-bit
frames made from them (`tests/digests.txt`). Framework-free, no file IO, nothing allocated after
`Part::new` (or `Voice::new`), no dependencies, builds for `wasm32-unknown-unknown`.

Made for an MXM instrument, MXM Modal Synth, as mxm-macro-osc was for MXM Thanks EG; its README's
claim is that it is bit identical to the original, and every rule below keeps that claim true.

# Local Contracts

## A file is ported from one file, as it is

- **One Rust module per C++ file**, at the same path, in snake case; types keep their C++ names,
  functions and methods become snake case, constants `K_MAX_BLOCK_SIZE` for `kMaxBlockSize`.
- Each module opens with where it came from: `//! Ported from elements/dsp/voice.{h,cc}` and the
  original's copyright line (`Copyright 2014 Emilie Gillet.`), MIT as `NOTICE.md` says.
- **No redesign while porting.** The structure, the order of statements and the names follow the
  C++, so the port reads line for line beside it.

## The bits

- **f32 arithmetic in the C++'s order.** Never `mul_add`, never reassociate, never fold a constant
  the C++ computes at run time.
- **C++'s promotions, exactly.** A literal without `f` (`fabs(bow) + 0.75` in the resonator) is a
  `double`: the expression is computed in f64 and converted where the C++ converts.
- **Float to integer as MSVC x64 does**, through `stmlib::dsp::dsp`'s helpers, never a bare `as`
  (mxm-macro-osc's measured rules: to `int32_t` truncation, a NaN or out-of-range value giving
  `i32::MIN`; to `uint32_t` the low 32 bits of a 64-bit conversion; to `size_t` `cast_usize`).
- **An `int32_t` added to a `size_t`** (the delay lines' `write_ptr_ + delay_integral`) is
  converted to `size_t` first, a negative one wrapping, before the `%`.
- **`std::max`, `std::min` and `CONSTRAIN` as C++ evaluates them** (`cpp.rs`), never `f32::max`,
  `min` or `clamp`; a table indexed by an integer from a float reads through `cpp::at`, which
  never panics.
- **The part starts zeroed**, as the firmware's static one does, before `init`: a field the C++'s
  `Init` never sets (`Part`'s `panic_`, the resonator's `clock_divider_` and LFO phase, the
  string's `src_phase_`, the reverb's lows, the hidden voice's `damping_` and `feedback_`, the
  tube's delay line) keeps that zero and carries on across an `init`, with a comment saying so.
- **An interpolator writes back at the end of its scope**, as the C++ destructor does (`Drop`).
- **The maths library**: at run time Elements calls only `fabs`, exact in Rust (`f32::abs`). Its
  two other calls, `sinf` in `NaiveSvf::set_f_q<FREQUENCY_EXACT>` from the hidden voice's `Init`,
  take two constants; their results are the reference build's own bits (`0x3ea0305c`,
  `0x3f1e377a`, read off the filters after `Part::Init` by the harness's `--constants`), kept in
  `stmlib::dsp::filter`. Any other exact path (`tanf`, `cosf`) is a compile error.
- **No change from the C++**, not the rate (32 kHz, as the module's codec), nothing.
- **No denormal guard**: the reference was rendered with flush-to-zero on, and a host that wants
  its bits sets the same; a guard of the port's own would change them.

## Randomness

- **One `Random` per voice** (stmlib's LCG, its state starting at `0x21`), owned by the `Voice` and
  passed by `&mut` to the exciters and strings, in the C++'s order. The C++ has one static
  generator for the whole module; a voice here draws exactly what the module's one voice draws.
  `Voice::init` does not reset it, as the C++ never resets its generator.

## The interface

- `Patch`, `PerformanceState` and `Part` as `dsp/patch.h` and `dsp/part.h` have them;
  `Part::new() -> Box<Part>` makes the static object's zeros, `init` is `Part::Init` (the reverb
  owns the memory `elements.cc` hands it), `process(&PerformanceState, blow_in, strike_in, main,
  aux, size)` once per block of up to 16. `Part::Panic`, declared and never defined, is not.
- `Voice`, `OminousVoice` and `fx::reverb::Reverb` are public for a host that builds its own
  polyphonic part. For a host, and not in the C++: `Voice::envelope` and `OminousVoice::envelope`
  read the exciter's envelope (a *Contour* source), `Voice::random_mut` the voice's stream, and
  `clear` (on the voices, the reverb and every part with memory) returns an object to what `new`
  made, allocating nothing, for a host's reset (`tests/clear.rs`). None of them changes a bit of
  `process`.
- Not ported: everything of the hardware's (panel, settings, calibration, drivers), and the
  firmware's `cv_scaler.cc` and `elements.cc` around the part, but for `SoftConvert`, which the
  harness and the tests apply as `elements.cc` does.

## Clippy

- **A clippy rewrite that would change the rounding or the C++'s form is declined**, crate-wide
  allows only for lints the whole port trips, each with its reason (`lib.rs`).

## Realtime

No allocation, no locks and no panic on any input in `process`; overflow is handled as the C++
handles it, never by a debug panic. `#![forbid(unsafe_code)]`.

# Work Guidance

- **A digest comes from the C++, never from this port.** The harness that renders Elements' C++
  is not in this repository: a new case is rendered by Elements' part built as
  `tests/cases/README.md` says (MSVC, x64, `/O2 /fp:precise`, flush-to-zero), and its SHA-256s go
  into `tests/digests.txt`.
- The C++ is `pichenettes/eurorack` at the commit above; port from it, not from memory, and not
  from another port.
- **The README's claims are checked facts**: 106 cases, every one bit for bit, floats and frames,
  checked on Windows x86-64; no maths library call but `abs`. A change that alters one changes the
  README with it.
- Editing a file from Python: open it with `encoding='utf-8', newline=''`; a commit message goes
  through `git commit -F <file>`.

# Verification

```bash
cargo test                           # every case, bit for bit; the README's example
# A mismatch: MXM_MODAL_VOICE_CASE=<case> runs one; MXM_MODAL_VOICE_RAW_DIR=<dir> writes its

cargo clippy --all-targets -- -D warnings
cargo fmt --all -- --check
cargo build --target wasm32-unknown-unknown
```
